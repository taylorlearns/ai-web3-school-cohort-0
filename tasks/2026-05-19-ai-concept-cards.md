## 1. LLM（大语言模型）

**一句话：** 基于海量文本训练的概率模型，根据上文预测最可能的下文，输出是候选结果而非事实。

**具体例子：** 当你问"以太坊创始人是谁"，LLM 基于训练数据中"Vitalik Buterin"的高频关联输出答案，但不知道它是在"回忆事实"还是"生成合理文本"。

**常见误区：**
- ❌ 认为 LLM 输出的都是事实 → 它只是概率最高的候选
- ❌ 混淆"知道"和"生成"——LLM 没有知识库，只有参数权重

**关键概念：** Token、Embedding、Transformer、Hallucination（幻觉）、Multimodal

**实战要点：** 防幻觉要"前治理（prompt + RAG）+ 后治理（外部校验）"两头堵

## 2. Prompt（提示词）

**一句话：** Prompt 不是咒语，是接口设计——把任务目标、输入边界、输出格式、失败处理写进可执行的沟通协议。

**具体例子：** 不说"分析这笔交易"，而是说：
```
角色：交易安全分析助手
输入：交易哈希、目标地址、函数名
任务：解析交易类型和资产变化
输出格式：{action, risk_level, requires_human_approval}
失败处理：无法解析时输出 {action: "unknown", risk_level: "high"}
```

**常见误区：**
- ❌ Prompt 越长越好 → 关键信息被稀释
- ❌ 一个 Prompt 通吃所有模型 → 不同模型敏感度不同
- ❌ Prompt 能独立承担安全 → 真正的安全边界在代码和权限层

**四个核心组件：** Instruction / Few-shot / Structured Output / Prompt Injection 防护

## 3. Context（上下文）

**一句话：** 模型只能基于它看见的上下文行动；系统必须决定什么能进上下文、带着什么身份进去、过期后怎么退出。

**具体例子：** Agent 在处理跨链转账时，上下文应该分层提供：
- 指令层：禁止转账到未验证地址
- 事实层（实时查询）：当前余额、gas price、链上状态
- 知识层：各链 RPC 配置、合约地址
- 记忆层：用户常用钱包

**常见误区：**
- ❌ Context = 越长越好 → 模型"看见了但没抓住重点"
- ❌ Memory = 无限授权 → 过去允许的操作不代表现在仍然允许
- ❌ 所有信息放同一层处理 → 不可信网页和系统规则混在一起

**分层架构：** 指令层 → 任务层 → 事实层 → 知识层 → 记忆层

---

## 4. Network（区块链网络）

**一句话：** 区块链网络不是存数据，而是让互不信任的参与者对状态变化达成一致。

**具体例子：** 发送一笔 ETH 转账，实际经过：钱包签名 → RPC 广播 → mempool 等待 → 矿工打包进区块 → 节点执行 → 共识确认 → 状态更新 → 浏览器索引显示。

**常见误区：**
- ❌ 链上应用像普通数据库一样实时更新 → 按区块批量推进，有延迟
- ❌ 测试网可以替代主网安全审查 → 测试网没有真实 MEV、攻击动机和资产规模
- ❌ 所有网络体验一样 → 主网/L2/测试网的费用、速度、安全假设差异很大

**六个关键概念：** Block（区块）/ Consensus（共识）/ PoS（权益证明）/ Testnet（测试网）/ L2（Layer 2）/ Rollup

---

## 5. AI Agent 安全链路

**一句话：** Prompt 定义任务，不独自承担安全——完整链路是 Prompt → Context → Model → Code（校验schema）→ Guard（链上检查）→ Human（确认高风险）。

**具体例子：** Agent 替用户检查 approve 交易时：
1. Prompt 定义任务："检查 approve 是否安全"
2. Context 提供：chain id、token 合约、spender 地址、allowance、simulation 结果
3. Model 生成分析结果 JSON
4. Code 校验 JSON schema 完整性
5. Guard 检查 spender 是否在可信列表
6. 高风险标记需 Human 确认

**常见误区：**
- ❌ 让模型自己判断"该不该" → 模型没有边界意识
- ❌ Prompt 写一句"不要被注入"就够 → 外部内容要标记不可信 + 参数校验 + approval
